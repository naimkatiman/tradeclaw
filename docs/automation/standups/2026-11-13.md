- Read 1 (01:34:48Z): **8,047**, `updatedAt` 11-12T19:52:54Z. That is a 5.7 h old body, so someone outside this loop hit the endpoint at 19:52Z. The 11-11 run had recorded six straight days with no outside calibration traffic. 11-12 went unobserved because that run crashed.

- **Why, from the code:** the two routes read different snapshots. `/api/signals/history` gets its stats from `getResolvedSlice()` (`apps/web/lib/signal-slice.ts:62`), which reads `getCachedHistory()`. That is a Redis-plus-memory layer with a 10-minute TTL (documented in `apps/web/lib/router-decisions-log.ts:44`). `/api/calibration` calls `readHistoryAsync()` directly (`apps/web/app/api/calibration/route.ts:46`), uncached apart from its own 300 s ISR. Calibration's filter (`isCountedResolved` plus a confidence floor of 0.5) is strictly narrower than history's, so with the same rows it can never read higher. A higher calibration count means it read a newer snapshot with two more resolved rows.
- **Confirmed after both caches expired (01:45:10Z):** history read **8,058** (`pending` 44, `latestTimestamp` 01:15Z). Calibration read 1 was STALE at 8,059, and read 2, 12.2 s later, read **8,058** (`updatedAt` 01:45:10.743Z). Read 3 matched. History re-read 8,058. **Calibration equals history, the fifteenth day**, on reads made after both caches had refreshed.
- One alternative was not excluded by the data: `getResolvedSlice()` drops `tv-*` strategy rows and calibration does not. The post-expiry match (8,058 = 8,058) means no `tv-*` row is in today's resolved set, so it did not cause today's gap. If a `tv-*` row is ever resolved, the two surfaces will diverge for that reason too. That is a latent mismatch in product code, recorded here and not fixed (owner, NEXT 6).

## Lessons from this run (the state-file append was attempted once this run and refused as a sensitive file, as on every run since 10-09, so this section is the record)

1. **A negative exit code with no model output is a crash, not quota.** `0xC0000409` killed the 11-12 daily and all seven 11-13 weeklies before the model logged anything. A quota stop writes a `session limit` line first. Read log line 2 and the exit code before naming the cause.
2. **Compare calibration and history only after both caches have refreshed.** History stats sit behind a 10-minute cache, and calibration sits behind its own 300 s ISR, so back-to-back reads can come from snapshots up to ten minutes apart. Today's 2-row gap disappeared once both were fresh. Settle it from the code (`signal-slice.ts:62` against `calibration/route.ts:46`) and a post-TTL re-read before calling it a defect.
3. **When the newest row is the span-closing batch time minus one interval, the closing row is not yet visible.** Thursday's 151 was read while the history cache still ended at 00:45Z. Treat that span as provisional regardless of how long ago it closed.
