### The naming asymmetry that makes this trap easy to fall into

- **Daily** logs are named with the **batch** stamp. All eight projects share `daily-2026-09-06_1634.log`.
- **Weekly** logs are named with **each project's own start** stamp: `1634 / 1702 / 1722 / 1739 / 1756 / 1812 / 1824`.

A glob keyed on batch stamps therefore finds every daily in a batch but only the *first* weekly. The 09-06 daily's method was sound for dailies — which is exactly why it produced a confident wrong answer for weeklies.

### Class D — premature-loss report (new failure class)

The existing taxonomy covers under-reporting:

- **A** — ran and failed; gate correctly returns FAIL. (6 dates, 8 runs.)
- **B1** — artifact written, never committed. (08-27.)
- **B2** — committed, never pushed. (09-03 07:24.)
- **C** — launcher never fired; no run record at all. (Reclassified 09-06 as host unavailability, not a loop defect.)

**Class D is over-reporting: the loop records a loss that has not occurred, by evaluating an in-flight process as terminal.**

D is more corrosive than A–C. A–C leave a real gap and a silent or honest record; the next run can find the gap. D leaves *no* gap and a record asserting one. It contaminates the ledger the next run resumes from — and this loop resumes from its own prior standup by design. Absent today's check, "the 09-04 weekly is gone" would have been carried forward as settled fact into every subsequent standup, exactly as the Class C framing was carried from 09-03 to 09-06 before being corrected.

The guard is one rule: **before reporting a scheduled run as lost, establish that it is terminal, not merely unstarted.** A run is terminal when it has a row in `loops/state/<project>.STATE.md` with a verdict, or when its whole batch window has demonstrably closed. Absence of a per-project log inside an actively running batch is evidence of *not yet*, never of *never*.

## Lessons (durable)

1. **An in-flight serial batch is not evidence of exclusion.** Absence of a per-project log while its batch is still walking the queue means *not yet*, not *never*. Check the batch launcher log and the state-file verdict row before declaring any scheduled run lost.
2. **Log-naming convention differs between daily and weekly batches.** Dailies share one batch stamp across all projects; weeklies carry each project's own start stamp. A glob keyed on batch stamps finds every daily and only the first weekly. This is what made the 09-06 error look rigorous.
3. **A correct mechanism can be attached to a non-fact.** `promptFile.weekly: null` is true and was verified twice. It explained an event that never happened. Verifying the *mechanism* is not verifying the *event*.
4. **`git status --porcelain` collapses untracked directories; `-uall` does not.** The two figures differ by 22 here (42 vs 64). Any count carried across standups must name which form produced it, or a directory rollup reads as file loss.
5. **Distinguish a permission denial from a tool failure.** graphify was denied before execution today and errored on a missing key on four prior days. Collapsing them into "failed a 5th time" would fabricate four counter values that were never measured.
