## Headline — the 08:17 fire is the *missed 09-10 run catching up*, not an early 09-11 run, and catch-up runs are RUN-dated, which is why 09-10 can never have a standup

Windows Task Scheduler does not fire a trigger *before* its scheduled time. A 09:30 trigger cannot
produce an 08:17 run of 09-11. The only mechanism consistent with its semantics is
"run task as soon as possible after a scheduled start is missed": the host was asleep across
09-10 09:30, woke this morning, and the queued 09-10 run fired at 08:17 today.

This is not an inference from one case. The launcher log directory records **five** early-morning
off-slot fires, and every single one is immediately preceded by at least one date with zero logs
for any project:

| `daily-2026-08-20_0606` | 08-14 … 08-19 | yes — `daily-2026-08-20_0930` |

The 09-06 standup got the mechanism right ("missed-run catch-up on wake") and stopped there.

### Root cause: two schedulers, one repo, no mutex

The 08:17 host wake fired **both** missed batches, not one. The eight `daily-*_0817.log` files and
`weekly-all-2026-09-11_0817.log` share a stamp. Each batch is serial internally (the 09-07
finding), but nothing serializes the two batches against each other, and nothing serializes either
batch against the separate on-slot 09:30 daily trigger.

The weekly batch order reproduced **exactly**, a third independent confirmation of the 09-07 model:

| Position | 2026-09-06 | 2026-09-11 |
|---|---|---|
| 1 | DrSaid 16:34 | DrSaid 08:17 |
| 2 | MosRev 17:02 | MosRev 08:40 |
| 3 | continuous-improvement 17:22 | continuous-improvement 09:08 |
| 4 | **tradeclaw 17:39** | **tradeclaw 09:22** |

Order is identical. Arrival lag from batch start is 65 minutes in both samples.

**Do not treat 65 as a constant.** The per-leg splits differ — 28/20/17 on 09-06 against 23/28/14
today — so two runs summing to the same total on different legs is most likely coincidence at
n=2, not a law. The safe planning number is "tradeclaw's weekly lands roughly an hour after the
weekly batch starts, ±10 minutes," and the load-bearing fact is the **position**, which is
config-determined and stable.

### Why that matters: the collision is predictable and will recur

A weekly batch that starts anywhere in roughly 08:00–09:30 puts tradeclaw's weekly on top of the
09:30 daily. Today it started at 08:17, landed at 09:22, and the weekly's own runtime — DrSaid took
23 minutes, MosRev 28 — guarantees it is still working when the daily fires 8 minutes later. That
is not a freak alignment. It is what happens on **any Friday the host misses its morning slot**,
because the catch-up wake fires the weekly batch and the on-slot daily trigger independently.

### The operational consequence: stage-then-commit is unsafe here

A shared checkout means a shared index. If the weekly runs `git add docs/research/weekly-research-2026-09-11.md`
while this run has `docs/automation/standups/2026-09-11.md` staged, whichever process commits first
commits **both** paths. Two concrete failures follow, and the second is the dangerous one:

1. The standup commit bundles a research artifact — a violation of one-concern-per-commit, and
   potentially a **half-written** weekly artifact.
2. The loser's `git commit` finds nothing staged, exits non-zero, and leaves the artifact
   uncommitted — Class B1 from 08-27, the failure the gate provably cannot see (`gate.ps1`
   re-verified at source this run: its only git call is `branch --show-current` at line 51; checks
   are `Test-Path` at 34, non-empty at 38, `MinLines` at 41–42, branch name at 51–56).

Label: the bundling **mechanism** is inferred from how git's index works, not observed today — no
collision actually occurred, because the weekly had not reached its commit step. The mitigation is
free either way, so it is applied rather than debated.

**Fix applied this run:** commit with the pathspec form, `git commit <path> -m ...`, which commits
only the named path and ignores whatever else sits in the shared index. No `git add`. This is
strictly stronger than "stage by explicit path," which every prior standup used and which is
sufficient against autocrlf but **not** against a second writer.
