## Lessons from this run (the state-file append was attempted once this run and refused as a sensitive file, as on every run since 10-09, so this section is the record)

1. **Decode every epoch before naming the bar.** 11-09 labelled 1794096000000 as the 11-09 bar. It is 11-08. Run one `new Date(ts).toISOString()` before quoting any `barTimestamp` or id-suffix date.
2. **Space calibration reads by several seconds.** A second read 0.3 s after the stale hit returned the same stale body, even though the rebuild had already finished (its stamp falls between the two reads). The 10-15 "probe twice" rule assumed about 7 s between reads. Make the gap explicit.
3. **A sliding-window prediction needs an age bound.** "Exactly the four D1 rows" failed because the oldest of them aged out of the newest 800. Name each row's date in the prediction, or say "only D1 rows".
4. **Scan every source class before scoping a defect to one asset class.** The 11-09 "FX only" scope came from the null-aged set, which already excluded the equity rows that had their placeholder. A one-line `source === 'force-expired'` filter over the whole window found four more.
