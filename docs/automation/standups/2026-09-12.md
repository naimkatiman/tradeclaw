### Answer: adding a terminal status does NOT re-hash the frozen rule. Three independent reasons, all at source.

Source read: `git show origin/main:apps/web/lib/d1-alpha-protocol.ts` (see next section for why `origin/main` and not the working tree).

1. **The hashes are frozen literals, not derived values.** `D1_ALPHA_RULE_SHA256` (lines 6–7) and `D1_ALPHA_ARTIFACT_SHA256` (lines 8–9) are `as const` string literals, typed into the payload as `typeof`. No code path in the module recomputes them from source. Changing a function cannot change a literal.
2. **The gate verdict is not in the hashed object.** `D1AlphaSnapshotPayload` (lines 66–83) carries `schemaVersion`, `strategyVersion`, the two shas, `barTimestamp`, both sleeves, four NAV fields, four cost/funding increments and `closedTradesIncrement`. `status` is not in it. `status: D1AlphaStatus` lives at line 105 inside a **separate** interface, `D1AlphaGateEvaluation` (lines 104–120).
3. **The only hash in the module chains the payload, nothing else.** `hashD1AlphaSnapshot` (lines 194–200) is `sha256(previousHash ?? 'GENESIS' + "\n" + canonicalD1AlphaPayload(payload))`, and `canonicalD1AlphaPayload` (line 190) stringifies the canonicalised **payload**. `evaluateD1AlphaGate` (line 444) is a pure function of `metrics` plus two booleans, and its return value never reaches `buildD1AlphaHashedSnapshot` (line 487).

So the implementer's first question resolves cleanly: a new `D1AlphaStatus` member changes no rowHash, breaks no chain, and cannot move `ruleSha256`/`artifactSha256`. **The risk the digest raised is not a real blocker.** Recording that is worth more than the proposal it unblocks, because it is the first time this corpus has closed a grill finding instead of carrying it.
